你在协助光伏企业（晶澳）HR 系统做岗位说明书（JD）精析。这是「读文件 + 推理 + 写一个 JSON 文件」的任务：不要调用外部 API、不要联网、不要改其他文件。

## 输入

- 批次文件（绝对路径，`prepare` 渲染时填入）：`<BATCH_PATH>`——数组，含 **1~N 个岗位**，每个含
  `job_id`、`job_name`、`department`、`org`、`work_location`、`responsibilities`（岗位职责原文）、
  `requirements`（任职要求原文）、`current_hard_gates` / `current_must` / `current_bonus`（脚本词表粗提取，可能很粗）。
- 词表参考文件（绝对路径，`prepare` 渲染时填入）：`<VOCAB_PATH>`——
  **简历库候选人技能标签池**（运行时从简历表 skills 列实值派生）——岗位用词必须与之同源，
  因为匹配打分就是拿岗位词对简历词。文件不存在或为空（简历未入库/未精析）时，
  以本批 `current_must`/`current_bonus` 与 JD 原文行业短词为准，不必报错。

通读 responsibilities 与 requirements，产出三个字段。

## 1. hard_gates（硬性门槛，字符串）

**固定五段，分号分隔；缺项尽量写"不作硬性要求"**（漏写也不要紧：merge 会按段序自动补齐，
但主动写全可避免下游把"JD 未提"误读成"漏析"）：

```
学历：本科及以上 / 大专及以上（有"放宽至大专"等条款要原样保留）；专业：…等相关专业；经验：N年及以上…；证书：…；年龄：…
```

只写**一票否决项**。判断要点：
- "优秀者可放宽""优先"不算硬性要求，但要留在括号里，避免下游误删；
- 经验年限按 JD 原文最低值（如"2-3年"写 2年及以上）；
- 证书要具体到证名（注册安全工程师、中级会计师、高低压电工证…），JD 写"等"字时保留"等"。

## 2. must_skills（必备技能，字符串）

从职责与技能要求提炼**尽量 6-10 个短词**，用「、」分隔：
- 字数是**软偏好、无硬上限、无机器拒收**：中文短词优先（读起来自然、与简历标签同源），
  但长术语一律照写不删——无论是 7 字中文术语（如「质量管理体系认证」）还是长英文术语
  （如「Continuous Plating Line」），过长的词只会被 merge 记为**观察（over_len_words）**
  供人工过目，绝不丢行。
  具体字数口径的唯一真源是代码（`jobs_analyze.observation_specs` + `shared/soften.py`），此处不复述数字。
- 具体可验证；禁止"沟通能力""抗压能力""责任心"这类软词，也禁止"Excel/Word/办公软件"这类无区分度词（除非 JD 明确把它写成核心要求）。
- **词表必须与技能标签池同源**：优先复用 `<VOCAB_PATH>`（如存在）、`current_must` 里已有的合理词、
  以及 JD 原文实际出现的行业短词（如「暖通」「单晶炉」「丝网印刷机」）。
  同义不同形会让匹配打分恒为 0（岗位写"账务处理"而候选人标签是"总账处理"就是实测教训）。
- 每一项都要能在 JD 原文里找到依据，不要编造。

## 3. bonus_skills（加分项，字符串）

**尽量 4-8 个短词**，「、」分隔：JD 里写"优先""加分""有经验者"的内容，以及该岗位做得好会出格的技能
（证书、行业背景、项目类型、工具、带团队等）。与 must_skills 重复也无妨——merge 会自动把重复词从
bonus 去重（保留在 must），不必你手工回避。

## 输出

写入与批次文件同目录、**文件名由输入自派生**的 done 文件（输入 `jobs_pending_part<N>.json` →
输出 `jobs_done_part<N>.json`，把 pending 换成 done，N 不变），格式：

```json
[{"job_id": "J3D5C031FB9",
  "hard_gates": "学历：本科及以上；专业：财会相关专业；经验：2年以上财务工作经验；证书：初级会计师及以上；年龄：25-40岁",
  "must_skills": "成本核算、财务核算、总账处理、存货盘点、成本分析、金蝶、纳税申报",
  "bonus_skills": "合并报表、预算管理、研发费用归集、ERP、高新申报"}]
```

要求：
1. **必须覆盖输入文件里的全部 job_id**，一条都不能漏；done 文件名与输入同目录、pending→done 派生（N 不变）；
2. **按上述 schema 输出即可，质量细节不必自纠**：`hard_gates` 尽量五段齐全（缺项可留空，merge 会自动补
   "不作硬性要求"），`must_skills`/`bonus_skills` 数量与字数是软偏好。**不需要也不要自己写/跑校验脚本**：
   merge 阶段由 `jobs_analyze.normalize_row` 自动修复格式（缺门槛段补"不作硬性要求"、must/bonus 重复词
   去重、半角标点转全角、数组转「、」串），质量问题只记为**非阻断观察（soft_observations）、照常写回**。
   **唯一会丢行的只有**：缺/重复 `job_id`，或三列（hard_gates/must_skills/bonus_skills）全空的行
   （L0 判定在 `jobs_analyze.validate_row`）——被丢的行保持未打 `ai_refined_at`、下一周期自动重析。
   你只 Write 一次、报告条数即可，把回合省到"读输入 → 推理 → 写产物"三步。
3. Windows 下写文件用绝对路径（`prepare` 已把本批路径填进上文，照抄即可）。
4. 回复≤80字：报告 job_id 个数与 2-3 个典型 must 词即可。
