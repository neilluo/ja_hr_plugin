你在协助一个光伏企业（晶澳）HR 系统做简历 AI 精析。这是「读文件 + 推理 + 写一个 JSON 文件」的任务：不要调用任何外部 API、不要联网、不要改动其他文件。

## 输入

- 批次文件（`prepare` 渲染时已填入本批绝对路径）：数组，每条含
  `id`、`name`、`current_skills`（脚本正则粗提取的，可能不准/不全）、`full_text`（简历全文，可能被截断）、
  `source_file`（原件本地绝对路径，扫描件时为唯一可用信息源，普通简历可为空）
- 词表文件（`<VOCAB_PATH>`，即仓库根下 `outputs/job_vocab.json`）
  —— 岗位必备/加分技能同源词表，**选词优先与它一致**（否则后续匹配打分会对不上）

**先分流，再精析**（两条路径产出的全部字段——三列 + <CORR_N> 个基础字段校正——完全同规格）：

- `full_text` 非空 → 直接通读 `full_text` 产出全部字段（三列 + <CORR_N> 个校正字段，下述规则一致）。
- `full_text` 为空且 `source_file` 非空 → 这是扫描件/图片简历，**必须先用 Read 工具读原件**
  （Read 可直接读 PDF 与图片，多页 PDF 逐页读全部页），据看到的版面内容产出全部字段。
  读图纪律：同一批次内的多份原件必须在**同一条消息里一次性并发发出所有 Read 调用**，
  禁止一份一回合串行读；`source_file` 指向的文件不存在或读不出内容时，该条三个字段一律输出
  `skills: []` 与"未提及"填充、<CORR_N> 个校正字段一律输出 `null`，**禁止编造**。
- 两者皆空 → 该条输出 `skills: []`、`ai_structured` <SEGS_N> 段全填"未提及"、`ai_deep` 写
  "亮点：无 风险：原件与文本均缺失 建议：人工补录"、<CORR_N> 个校正字段一律 `null`，不要跳过该条。

## 1. skills（技能标签数组）

提炼该候选人真实、可验证的硬技能/专业标签：
- 简体中文，具体不空泛。禁止"学习能力""团队合作""抗压能力"这类软素质词。
- 字数偏好（**软性引导，非机检门槛**）：尽量用简短术语，中文标签以 <SKILL_ZH_RANGE> 字为宜；
  纯英文/缩写术语（如 PLC、CAD、SolidWorks、K8s、YOLO、MES、Docker、MySQL）不受此限，
  也没有字符数上限。**不会因字数被机器拒收**——超长标签只会被 merge 记为一条非阻断观察
  （observations），照常写回。遇到"热镀铝锌硅钢板""扫描电子显微镜""质量管理体系认证"这类
  标准长术语，照写不误，不要为了凑字数砍掉术语或改写成含糊短词。
- 优先从 `<VOCAB_PATH>`（job_vocab.json 岗位必备/加分技能同源词表）与简历内容里选词；
  示例（不是穷举，最终以 job_vocab.json 与简历实际内容为准）：单晶、拉晶、丝网印刷、PLC、SolidWorks。
- 词表外确有的硬技能可直接新增（如"焊接机器人""AOI""SPC"）。
- 数量**尽量 <SKILLS_RANGE> 个**（软目标），按重要性排序；不足不要硬凑、更不要编造；纠正 `current_skills` 里明显错抓的词（如把"Excel""成本"当技能、
  把"助理工程师/高级电工证"这类职级或证书混进技能）。
- 判"无内容可析"的依据是**实际读到的简历内容**（`full_text` 或读图所得）为乱码/空/与技能无关，
  此时输出 `[]`；仅 `full_text` 为空不构成该条件（扫描件走读图）。
- **不要编造简历中未提及的技能。**

## 2. ai_structured（AI 结构化提取，字符串）

固定 <SEGS_N> 段，每段一行，段名后用"｜"分隔：

```
<SEG_1>｜<最高学历> <院校> <专业> <院校层次判断>
<SEG_2>｜<总年限>年，<最近一份工作的公司+岗位+时长>，<行业关键词>
（<总年限> 只写纯数字如 `4年`，禁止「约4年/近4年/4年以上」；简历未明写时按经历时间段做减法估出数字。
此数字须与校正字段 `years_experience` 一致）
<SEG_3>｜<Top 5 硬技能，逗号分隔>
<SEG_4>｜<期望职位> <期望地点> <期望薪资>
<SEG_5>｜<一句话判断适合什么岗位/产线，如"适合单晶拉棒产线设备工程师">
```

某段信息缺失用"未提及"填充，不要编造。整段控制在 <TEXT_MAX> 字以内。

## 3. ai_deep（AI 深度解析，字符串）

给 HR 的决策参考：
- **亮点**：1-2 条最突出优势，必须具体到项目/指标/金额/年限（如"年运维成本节约1400万元"）
- **风险**：1-2 条顾虑（跳槽频繁/空窗期/技能与岗位偏差/学历短板等），没有就写"无明显风险"
- **建议**：一句话（"建议安排技术面""可作储备""暂不推荐"等）

整段控制在 <TEXT_MAX> 字以内，自然语言，不用列表符号。

## 4. 基础字段校正（<CORR_N> 个，可为 null）

你反正已逐份读全文，顺带校正脚本正则粗提取的基础档案字段。每条记录必须输出以下 <CORR_N> 个字段
（字段名=业务键，与表列一一对应）：

- `<CORR_1>`：**仅当**简历原件正文明确显示的姓名与输入的 `name` 不同时，才输出原件真值；
  相同或原件无姓名时输出 `null`。
- `<CORR_2>`：原件真实载明的所学专业（最高学历对应的专业）。无法确定输出 `null`。
- `<CORR_3>`：原件真实载明的毕业院校全名（独立学院要完整，如"贵州财经大学商务学院"）。无法确定输出 `null`。
- `<CORR_4>`：原件真实载明的证书清单，多个证书用「、」连接成**一个字符串**
  （如"低压电工证、特种作业操作证"）。无证书或无法确定输出 `null`。
- `<CORR_5>`：**整数**，按工作经历时间线推算的总年限（经历时间段做减法；应届/在读给 `0`，
  只有实习经历给实际实习年数）。无法确定输出 `null`。
- `<CORR_6>`：原件真实载明的期望/应聘职位，多职位用「、」连接成一个字符串。无法确定输出 `null`。

铁律：**只输出简历原件真实载明的值，无法确定一律输出 `null`，禁止猜测**。`null` 不会覆盖表内已有值，
猜错的值会——宁可 null。

## 输出

把结果写入与批次文件同目录、**文件名由输入自派生**的 done 文件（输入 `skills_pending_part<N>.json` →
输出 `skills_done_part<N>.json`，把 pending 换成 done，N 不变），格式：

```json
[
  {
    "id": "recordId",
    "skills": ["技能1", "技能2"],
    "ai_structured": "<SEG_1>｜本科 昆明理工 材料工程 普通本科\n<SEG_2>｜...",
    "ai_deep": "亮点：… 风险：… 建议：…",
    "<CORR_1>": null,
    "<CORR_2>": "材料科学与工程",
    "<CORR_3>": "昆明理工大学",
    "<CORR_4>": "低压电工证、特种作业操作证",
    "<CORR_5>": 4,
    "<CORR_6>": "组件工艺工程师"
  }
]
```

要求：
1. **必须覆盖输入文件里的全部 id**，一条都不能漏；done 文件名与输入同目录、pending→done 派生（N 不变）；
2. **尽量按上述 schema 输出**（字段名与类型见上文 JSON 示例：`skills` 是字符串数组、`ai_structured` 是含
   <SEGS_N> 段 `｜` 分隔的一整段字符串、`years_experience` 是 int 或 null、其余校正字段是字符串或 null）。
   **格式偏差不用你操心、merge 会自动归一化**：空行、半角竖线 `|`、缺段（自动补"未提及"）、
   多余段（自动并入上一段）、数组→字符串、`"1年"`→`1` 等一律由 `skills_analyze.normalize_row` 修复。
   质量问题（标签超长、技能数偏少、文本过长）只会被记为**非阻断观察**（observations），
   **不影响写回、不打回重析**。**唯一会丢行的只有 `id` 缺失或重复、或三列全空。**
   **不需要也不要自己写/跑校验脚本**：合规判定唯一真源在 merge 的 `validate_row`（L0）+
   `soft_observations`（L2 观察）。你只 Write 一次、报告条数即可，把回合省到"读输入 → 推理 → 写产物"三步。
3. 回复只需报告条数和 2-3 个典型标签例子，<TEXT_MAX> 字以内。
