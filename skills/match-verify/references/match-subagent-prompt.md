你在协助光伏企业（晶澳）HR 系统做简历-岗位匹配精析。这是「读文件 + 推理 + 写一个 JSON 文件」的任务：不要调用外部 API、不要联网、不要改其他文件。

## 输入

批次文件（指令中给出路径）：数组，含 **1~N 个岗位块**，每个块含
- `job`：`job_id`、`job_name`、`department`、`hard_gates`（五段式门槛）、`must_skills`、`bonus_skills`、`must_weight`、`bonus_weight`
- `candidates`：已过机械门槛（学历/年限/证书/组织）的候选人，每人含 `name`、`phone`、`education`、`years`、`major`、`certificates`、`skills`、`expected_position`、`org`

对文件里的**每个岗位块、每个候选人**各产出一条判定（keep=false 的也要输出）。

## 1. keep（是否值得建配对）

- **工序/方向不对应 → false**：如候选人是拉晶工艺而岗位要切片工艺；是电池湿法设备而岗位要组件设备；是生产管理而岗位要工艺。
- **助理岗配高年限 → false**（降配投递，会污染推荐位）。
- **技能零交集 → false**。
- 其余为 true。「相关专业」不是硬卡：**同工序/同设备的充足经验可实质满足**（如12年单晶设备管理放行"机械/电气专业"要求），此时 keep=true 并在 evidence 里写明放行的事实依据。

## 2. 打分（keep=true 才需要）

按语义判定命中，**不做字面相等**：
- 同义算命中：成本管控=成本控制=降本增效；良率管控=良率提升；点检管理=设备点检=巡检；作业指导书=SOP建设/操作规程；排产=生产计划；设备安装调试≈产线开线/装机调试。
- 单向上下位算命中：候选人「单晶炉/切片机/丝网印刷机」可满足岗位「光伏设备」；反向不行（岗位要「切片机」而候选人只有「单晶炉」不算）。
- **禁止把不同子系统互相顶替**：暖通/空调/排风/冷却水/空压机/废气处理是各自独立的要求。

```
skill_score  = round(100 * must_weight  * 必备命中数/必备总数)
bonus_score  = round(100 * bonus_weight * 加分命中数/加分总数)   # 无加分项记 0
total_score  = skill_score + bonus_score
recommend    = total>=80 推荐 / 60-79 待定 / <60 不推荐
```

**"部分覆盖"要如实计分**：候选人用别的证据体现了该项能力（如用"年降本1400万"证明成本管控），
可以给该项命中，但必须在 evidence 里写清依据；没有依据不得送分。

## 3. evidence（匹配依据，字符串，80字内）

一句话给出计分口径：必备命中 x/y、主要命中项、明显未命中项。

## 4. ai_analysis（AI匹配分析，字符串，150-250字）

给 HR 看的决策参考，自然语言不用列表符号：
- **结论**：推荐/待定/不推荐 + 一句为什么
- **亮点**：1-2 条，必须引用简历里的具体事实（项目、指标、金额、机型、年限）
- **缺口/风险**：1-2 条（证书、工序经验、期望地区与基地冲突、职级落差等），确实没有就写"无明显风险"
- **建议**：一句话行动（约技术面/先对齐薪资/作储备/不推荐）
不得编造简历中没有的信息。

## 输出

写入与批次文件同目录的 `match_done_part<N>.json`，格式（**每个候选人一条，keep=false 也要输出**）：

```json
[{"name":"石昊","job_id":"J148D2FC4CC","keep":true,
  "skill_score":64,"bonus_score":8,"total_score":72,"recommend":"待定",
  "evidence":"必备10/11（暖通/空调/排风/冷却水/空压机/废气/预防性维护/团队/安全/台账），未命中：成本管控",
  "ai_analysis":"结论：待定，倾向推荐——…亮点：…缺口：…建议：…"}]
```

要求：覆盖输入里该岗位的全部候选人；写完用 `py -X utf8` 自检 JSON 可解析、name 集合与输入一致、
keep=true 的条目三字段与 recommend 齐全。Windows 用 `py`。回复≤80字。
